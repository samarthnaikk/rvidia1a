Task: Fix Windows/WSL Docker + Iroh Failures in `docker-support-win` Without Regressing macOS

Branch Target
- Work only on branch: `docker-support-win`.
- Do not switch branches.

Hard Constraints
- Do not break or alter current macOS success path. macOS behavior must remain functionally identical unless a change is explicitly needed for shared correctness.
- Keep Linux/macOS defaults intact; add Windows/WSL-specific handling via guarded logic.
- Commit regularly in small, logical checkpoints (see commit plan below).

Current Failures to Solve
1. Host side fails to run container on Windows/WSL when GPU is not available:
   - `docker run ... --gpus all` exits with code `125`.
   - Error includes: `WSL environment detected but no adapters were found`.
   - Existing fallback detection does not catch this string reliably, so CPU fallback is skipped.

2. Receiver side fails to persist artifact ticket:
   - `iroh.iroh_ffi.IrohError` on `write_to_path`.
   - Fails for both primary and fallback path under `/mnt/c/.../backend/outputs/...`.
   - Existing fallback writes into same Windows-mounted filesystem and therefore does not mitigate.

Primary Goal
- Make Host execution resilient on Windows/WSL:
  - If GPU runtime is unavailable, automatically retry container on CPU and finish job.
- Make Receiver artifact persistence resilient on Windows/WSL:
  - If direct write to target path fails, download to Linux-native temp path and atomically copy/move into requested output path.
- Preserve macOS behavior as-is.

Files In Scope
- `backend/app/core/p2p_cli.py` (main changes)
- Optional minimal docs update if needed:
  - `backend/PROMPT.md` or `README.md` only for usage clarification (keep concise)

Implementation Requirements

1) Robust Docker GPU fallback in host flow
Target area: `_host_execute_docker(...)` in `backend/app/core/p2p_cli.py`

Current issue:
- Fallback only triggers for limited substrings:
  - `"could not select device driver"`
  - `"capabilities: [[gpu]]"`
- Windows/WSL error `"WSL environment detected but no adapters were found"` is not included, so command exits 125 and job fails.

Required changes:
- Add a helper:
  - `_is_gpu_runtime_unavailable(stderr_or_logs: str) -> bool`
- Return true for a broader set of case-insensitive signals, including:
  - `"could not select device driver"`
  - `"capabilities: [[gpu]]"`
  - `"nvidia-container-cli: initialization error"`
  - `"wsl environment detected but no adapters were found"`
  - `"no cuda-capable device"`
  - `"unknown runtime specified nvidia"` (defensive)
  - `"could not load nvml"` (defensive)
- Keep GPU-first behavior unchanged.
- If GPU run fails and helper returns true:
  - Log explicit message:
    - `GPU runtime unavailable on this host; retrying without --gpus all`
  - Retry `docker run` without GPU flags.
- If GPU run fails for non-GPU reasons, do not mask real failure; preserve failure path.
- Ensure final completion status reflects CPU fallback outcome (`success = run_rc == 0`).

2) Safer command construction for docker run/build/clone
Target area: `_host_execute_docker(...)`

Required changes:
- Replace shell-string concatenation for git/docker commands with argument-list subprocess execution where practical to avoid quoting/space issues on Windows paths.
- For volume mount, ensure host path is absolute and stable:
  - Use `Path.resolve()`.
  - Keep mount to `/outputs` only (security and compatibility).
- Preserve support for `--docker-args`, but parse safely:
  - Use `shlex.split(..., posix=False)` or equivalent guarded parser to avoid broken quoting on Windows.
  - If parsing fails, raise clear `RuntimeError` with hint.

3) WSL-aware artifact write fallback for iroh
Target area: `_download_ticket_to_path(...)` in `backend/app/core/p2p_cli.py`

Current issue:
- Primary and fallback paths both point to `/mnt/c/...`; both can fail similarly with iroh FFI.

Required changes:
- Keep existing primary behavior first:
  - Ensure parent exists.
  - Try write to requested absolute destination.
- On failure:
  - Log detailed diagnostics:
    - destination path
    - parent dir permissions (existing)
    - `platform.system()`
    - whether running in WSL (detected via `/proc/version` or env)
  - Attempt second strategy:
    - write ticket to Linux-native temp directory (e.g. `/tmp/rvidia-iroh/<uuid>/artifact.ext`) using `tempfile` + `Path`.
    - then copy to requested destination using Python file copy (`shutil.copy2`) or replace semantics.
  - Ensure destination parent exists before copy.
  - Return final destination path if copy succeeds.
- Optional third strategy:
  - If final copy to requested path fails, keep temp artifact and raise error that includes temp file path for manual recovery.
