------------------------------------------------------------------------------
Problem Hypothesis (likely root cause)
------------------------------------------------------------------------------
The signaling layer in `backend/app/routes/p2p.py` currently uses an in-memory dictionary:
- `_SIGNALS: dict[str, list[dict]] = {}`

This is fragile and can drop/miss messages when:
- backend restarts,
- more than one process/instance handles requests,
- host and renter hit different worker instances,
- transient request failures occur after queue mutation.

When `result_ticket` signals are lost/missed, renter never receives artifact tickets even though host ran successfully.

Additionally, there is no ACK/retry protocol for `result_ticket`, so delivery is at-most-once instead of at-least-once.

Required Fixes
------------------------------------------------------------------------------

1) Replace volatile in-memory signaling with durable DB-backed signaling
Files:
- `backend/app/models/` (new model)
- `backend/app/schemas/job.py` (request/response schema additions if needed)
- `backend/app/routes/p2p.py`
- `backend/run.py` (lightweight schema patch if migration framework is absent)

Implement:
- New `P2PSignal` table with fields:
  - `id` (UUID/string pk)
  - `job_id` (indexed)
  - `from_node_id`
  - `to_node_id` (indexed)
  - `signal_type` (offer/answer/candidate)
  - `payload` (Text JSON string)
  - `delivered` (bool default false)
  - `delivered_at` (nullable datetime)
  - `created_at` (datetime)
- Update push endpoints (`/offer`, `/answer`, `/candidate`) to insert rows instead of in-memory append.
- Update pull endpoint (`/signals`) to:
  - fetch undelivered signals for `job_id + to_node_id`, ordered by `created_at asc`,
  - return them,
  - mark only returned rows as delivered in same transaction.

Important:
- Keep API response shape compatible with existing CLI (`{"signals": [...]}`).
- Preserve existing participant access checks.

2) Add result-ticket delivery ACK + retry handshake
Files:
- `backend/app/core/p2p_cli.py`
- `backend/app/routes/p2p.py` (small new ack endpoint or signal message type)

Implement protocol:
- Host sends `result_ticket` signal with a unique `transfer_id` (UUID).
- Renter, after successfully downloading all artifacts + logs, sends `result_ack` containing:
  - `transfer_id`
  - `job_id`
  - status (`received`)
- Host waits for ACK with retry loop:
  - retries `result_ticket` push every 2-3 seconds up to timeout (e.g., 60 seconds),
  - stops retries immediately on ACK.
- If ACK not received in time, host marks job failed with explicit error:
  - `artifact delivery unacknowledged`
  - include `transfer_id` in logs for debugging.

Why:
- Prevents one-shot signal loss from causing silent no-artifact behavior.

3) Strengthen host artifact publication path
File:
- `backend/app/core/p2p_cli.py` (`_host_execute_docker`)

Required checks before pushing `result_ticket`:
- Verify `outputs/` scan result and print count:
  - `[RVIDIA] Collected N output file(s)`
- For each output file:
  - assert file exists and `stat().st_size >= 0`,
  - log file name + size,
  - on ticket generation failure, fail loudly with file-specific error.
- Include explicit log:
  - `[RVIDIA] Publishing result_ticket with X artifact ticket(s)`

Also:
- Keep fallback behavior that creates `artifact.txt` from runtime logs if outputs are empty.
- This fallback must remain cross-platform.

4) Strengthen renter artifact consume path
File:
- `backend/app/core/p2p_cli.py` (`run_receiver`, `_download_ticket_to_path`)

Implement:
- On receiving `result_ticket`, log transfer metadata:
  - transfer_id
  - number of artifact tickets
  - artifact names
- Fail fast if `artifact_tickets` empty and `artifact_ticket` empty.
- Add per-artifact retry on download/write:
  - e.g., retry each ticket up to 3 times with short delay.
- Resolve `output_dir` to absolute path and log final saved file paths.
- Send `result_ack` only after all artifacts + logs are fully written.

5) Preserve legacy compatibility
- Keep support for existing single-artifact fields:
  - `artifact_ticket`, `artifact_name`
- Keep new multi-artifact list:
  - `artifact_tickets`
- Keep signal payload JSON-compatible with current parser.

6) Add targeted observability (must-have logs)

- Renter:
  - result ticket receipt summary

These logs are required so missing-artifact bugs can be diagnosed from terminal output alone.

- `test_result_ticket_ack_flow.py`
